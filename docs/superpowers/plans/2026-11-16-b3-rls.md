# Phase B3 implementation plan: Postgres row-level security on Citus, with PgBouncer

> Light plan (process rules of 2026-11-16): goals, files, interfaces, acceptance tests. Signatures are binding.

## Header

- **Goal.** Every runtime query runs as `app_runtime` (NOBYPASSRLS) through PgBouncer under FORCE RLS, with the context set by `SET LOCAL` on BEGIN; cross-tenant work goes only through named system methods on a small `app_system` pool; identity and billing tables are distributed on Citus; a k6 gate bounds the cost.
- **Architecture.** Three roles from one init SQL; `DATABASE_URL` (runtime, pooled), `DATABASE_SYSTEM_URL` (system, pooled), `DATABASE_MIGRATION_URL` (owner, direct). `libs/database` owns the context builder, the unit-of-work helper, elevation, the system handle and the boot guard; each domain owns its distribution migration, its RLS migration (grants, helpers, policies) and its flow reordering. Nothing in `libs/` names a domain.
- **Spec paths (binding).** `docs/superpowers/specs/2026-10-12-domains-tenancy-rls-program-design.md` §4, §5.1, §8, §9, §13, §14, §16 ("spec §n"); `docs/superpowers/specs/2026-11-09-sharding-citus-pgbouncer-design.md` §2, §4-§7, §9 ("SH §n"); `docs/superpowers/specs/2026-11-09-stripe-ledger-immudb-design.md` §3, §5 ("LG §n"); contracts consumed: `2026-11-09-b2-core.md` I-1..I-8, `2026-11-09-b2-edge.md` Task 1/2/8/9 interfaces; `program-work/conventions.md` §2.12, §2.13, §4.11. Where inventory B3-6/B3-7 say `(select app.x())` or `set_config`, the specs win.
- **Upstream state.** Written against `feat/domains-tenancy` after S0 (`merge/s0e`: `startTestPostgres`, platform `0001_citus_helpers`, the runner's `configureCitusSession`), B2 core and B2 edge have merged. Next free migration indexes: platform `0002`, identity `0008`, billing `0002` (take the next free `NNNN` at merge time).

### Review Focus (the phase's one final review, `code-review high`; per-task reviews only where `review: yes`)

1. Every UUID that reaches `SET LOCAL` passes `RLS_UUID_PATTERN`; nothing else builds SQL from strings.
2. The runtime pool can never bypass: role attributes, FORCE RLS on every domain table, no grant on bookkeeping
   tables, no fallback URL; the boot guard fails closed (a failed or erroring check refuses in `enforce`).
3. `SystemDatabase` is injected only by `*.system-repository.ts`; the pinned method lists match spec §9; a
   `system`-scope method refuses outside `SystemContext`.
4. `elevate(permission)` checks in TypeScript first and never crosses tenants; `justified()` is reachable only
   from `*.elevated.ts`, takes a closed reason list and is scoped to its callback.
5. Policies: no subquery; helpers read reference tables only; both paths of every policy tested with exact rows;
   the users → memberships chain; `is_platform_staff` unreachable for `app_runtime`.
6. Which principal each unit of work runs as (tables in Tasks 12 and 16); every RLS spec with local execution off.

````text
[SH executive summary, items 1-3 and 8]
1. **Spec §8.1 fails on Citus.** A `set_config('app.tenant_id', $1, true)` on BEGIN never reaches a worker, so the
   shard query raised `app.user_id is not set` [P-5]. Citus propagates `SET LOCAL`, never `set_config()`.
2. **Use `SET LOCAL` instead.** Run `SET LOCAL app.user_id = '<uuid>'; SET LOCAL app.tenant_id = …; SET LOCAL
app.elevated = …`, with `ALTER ROLE app_runtime SET citus.propagate_set_commands = 'local'`. Citus prepends these
   to every remote BEGIN, including a mid-transaction elevate [P-5, P-6]. Verified through PgBouncer 1.26
   (transaction mode) with the repo's postgres.js: 200/200 correct, no leak, `prepare` true and false [P-12].
3. **No subqueries in policies.** Citus rejects them on distributed and reference tables [P-3]. Write `app.x()`, not
   `(select app.x())`. A cross-table check goes through a STABLE helper, and the helper may read only **reference**
   tables: one that reads a distributed table fails inside pushed-down joins [P-7, P-8].
8. **Single node needs no setup** [P-11], and Testcontainers works with the Citus image [P-13]. But local execution
   makes `set_config` look correct on one node [P-11b], so RLS int specs must set
   `citus.enable_local_execution=off`. All `citusdata/citus:14.2*` tags are amd64-only (emulated on Apple Silicon).

[SH §7.1: replaces the spec §8.1 "Context" bullet, its helper bullet and adds the cross-table bullet]
- **Context.** On `BEGIN`, the Drizzle transactional adapter sets three transaction-local settings in **one
  simple-protocol round trip**, from the CLS principal: `SET LOCAL app.user_id = '<uuid>'; SET LOCAL
app.tenant_id = '<uuid or empty>'; SET LOCAL app.elevated = 'on|off'`.
  - Values are never bound parameters (`SET` takes none). The adapter builds the string only from values that pass
    a strict UUID regex; anything else throws before SQL is sent.
  - `set_config()` is not used: Citus propagates `SET LOCAL` to the worker connections of the transaction (the
    role default `citus.propagate_set_commands = 'local'` on `app_runtime` and `app_system`), but never
    `set_config()`.
  - Transaction-local values cannot leak across pooled connections, and they work behind PgBouncer in
    transaction mode.
  - `elevate(permission)` issues `SET LOCAL app.elevated = 'on'` mid-transaction; Citus propagates it to
    connections that are already open.

- Policies call each helper directly (`app.tenant_id()`, never `(select app.tenant_id())`). Citus rejects subqueries
  in policies. The helpers are `STABLE`, and `user_id()`/`tenant_id()` read `nullif(current_setting(…, true), '')`.

- **Cross-table policy checks** go through `STABLE` helpers that read reference tables only (for example
  `identity.shares_current_tenant(user_id)` over `identity.memberships`; a helper that names a domain table lives
  in that domain's schema and migration set, not in `app`). A helper that reads a distributed table fails inside
  pushed-down queries.

[SH §7.3: role server settings, and the boot guard additions]
- `app_runtime`: `citus.propagate_set_commands = 'local'`, `statement_timeout = 15s`,
  `idle_in_transaction_session_timeout = 60s`;
- `app_system`: same;
- `app_owner`: none (the migrator sets sequential mode itself).

Boot guard additions: when `app.citus_enabled()`, refuse in production (and warn elsewhere) unless
`current_setting('citus.propagate_set_commands') = 'local'` for the runtime connection. Without it, every
remote shard query raises "app.user_id is not set": it fails closed, but loudly in every request.

[SH §7.2: spec §8.2 changes]
- **`identity.users` read:** `id = app.user_id() or identity.shares_current_tenant(id)`, where

  ```sql
  CREATE FUNCTION identity.shares_current_tenant(u uuid) RETURNS boolean LANGUAGE sql STABLE
    AS $$ SELECT EXISTS (SELECT 1 FROM identity.memberships m
                         WHERE m.tenant_id = app.tenant_id() AND m.user_id = u) $$;
  ```

  This helper names a domain table, so it belongs to the identity set (`identity.shares_current_tenant`), not the
  platform set. `libs/` names no domain.

- **`identity.tenants` read:** `id = app.tenant_id() or identity.is_member(id)`, using the same pattern.
- **All rows:** `(select app.x())` → `app.x()`.
````

**SQL names that cross tasks and phases.**

- Roles: `app_owner` (LOGIN, owns schemas and tables, `CREATE` on the database), `app_runtime` (LOGIN NOSUPERUSER
  NOBYPASSRLS), `app_system` (LOGIN NOSUPERUSER BYPASSRLS), `pgbouncer_auth` (LOGIN, production `auth_user`).
  Function `pgbouncer.get_auth(p_usename text) RETURNS TABLE (usename name, passwd text)` SECURITY DEFINER.
- Platform set `0002_rls_helpers`: `app.user_id() RETURNS uuid` (STABLE; raises SQLSTATE `42501`, message
  `app.user_id is not set`, when the setting is unset or empty), `app.tenant_id() RETURNS uuid` (STABLE; NULL when
  unset or empty), `app.elevated() RETURNS boolean` (STABLE; true only for the literal `on`).
- Identity set: `identity.shares_current_tenant(u uuid)`, `identity.is_member(t uuid)` (`LANGUAGE sql STABLE`) and
  `identity.staff_flag(u uuid)` (`plpgsql STABLE`), all `RETURNS boolean`, all reading reference tables only.
- Policy names: `<table>_<select|insert|update|delete>` `TO app_runtime`; `users_owner_select`,
  `users_owner_update` `TO app_owner` (the `staff:grant` path).
- Metrics: `db_system_calls_total{method,outcome}`, `db_rls_elevations_total{kind,name}`; pool label `system`.

**Grant model (deny by default).** No table default privileges: every table gets explicit per-table grants in its
domain's RLS migration, so a new table is unreachable until someone grants it. The platform set changes only
function defaults (`ALTER DEFAULT PRIVILEGES FOR ROLE app_owner REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC`).
`<schema>.__drizzle_migrations` gets no RLS and no grant to either app role.

**System-method ownership (spec §9 numbering).** B3 ships 1-5 and the `stripeEvents.markProcessedAsPlatform` half
of 8. G-1/G-3 add 6 and `outbox.insertAsPlatform`; L-10 adds 9-11 and `ledgerEntryRefs.recordAsSystem`; each adds
its method to its domain's pinned list (Tasks 11, 15) and its per-table `app_system` grants. Method 7
(`staff:grant`) is not a pool method: it connects as `app_owner`.

**Rules later phases inherit.** A table created after B3 carries in its own migration: the distribution call,
`ENABLE` + `FORCE ROW LEVEL SECURITY`, explicit grants, policies without subqueries, and a both-path policy spec;
the boot guard refuses a domain table without forced RLS. No password-reset flow exists today (code or B2 plans);
when one lands: token lookup as a `pre-auth` system method, then the write as `{ userId, tenantId: null }`.
